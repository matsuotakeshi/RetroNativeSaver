# RetroNativeSaver

Windows向けの、複数のゲーム映像をタイル表示するスクリーンセーバーです。libretroコアを各タイルの独立した子プロセスで実行し、グループ表示では複数モニターに **最大64画面を同時表示** できます。現在の版は **v0.22.4** です。

本体は **GNU GPL v3（GPL-3.0-only）** で公開しています。X1/libretroなどの第三者コードには、[個別のライセンス](THIRD_PARTY_NOTICES.md)が適用されます。

## 主な機能

- 複数モニターへの表示、タイルごとのROM抽選・フェード・周期変更。
- 左上のお気に入り枠、お気に入りごとの連続したボタン・キーボード入力。
- resource_group / resource_weightによる同時実行の負荷制限。
- ブラックリスト・ホワイトリストの管理、失敗したROMの再試行。
- 通常表示とグループ表示の起動時抽選。選ばれた機種グループのゲームを最大64枠に並べて表示。
- PC88・PC98・X1・X68000などの複数ディスク準備。対応機種一覧とコアの設定例は`systems.example/`を参照してください。

## 対応機種

RetroNativeSaverには、家庭用ゲーム機、携帯ゲーム機、アーケード、日本のクラシックPCを含む **38機種** の設定例が用意されています。

| カテゴリ | 機種 |
|---|---|
| 任天堂 | ファミリーコンピュータ（NES）、ファミコン ディスクシステム（FDS）、スーパーファミコン（SNES）、NINTENDO 64、ゲームボーイ、ゲームボーイカラー、ゲームボーイアドバンス、ニンテンドーDS、ニンテンドー3DS、ゲームキューブ、Wii |
| セガ | SG-1000、マスターシステム、ゲームギア、メガドライブ / Genesis、メガCD / Sega CD、セガサターン、ドリームキャスト |
| NEC | PCエンジン / TurboGrafx-16、PCエンジン CD-ROM²、PC-FX |
| ソニー | PlayStation、PlayStation 2、PSP |
| SNK | ネオジオCD、ネオジオポケット、ネオジオポケットカラー |
| バンダイ | ワンダースワン、ワンダースワンカラー |
| その他の家庭用ゲーム機 | 3DO |
| アーケード | FinalBurn Neo（FBNeo）、MAME |
| クラシックPC | MSX、PC-8801、PC-9801、シャープ X1、シャープ X68000、FM-7（試験的対応） |

**互換性について**

- 各機種に対応するlibretroコアが必要です。機種によっては、別途BIOSファイルも必要です。
- 性能と互換性は、コア、ゲーム、使用するPCによって異なります。
- すべての機種が64枠のグループ表示に対応しているわけではありません。
- FBNeoのグループ表示はメモリー使用量が多いため、初期設定では無効にしています。
- Nintendo 64は負荷が高くなる場合があり、特に複数を同時実行する際は多くの資源を必要とします。

設定例は`systems.example/`にあります。この一覧への掲載は、すべてのゲームや環境での動作を保証するものではありません。

## 最大64画面の同時エミュレーション

各タイルでは、独立した子プロセスがlibretroコアとROMを読み込み、ゲームを実行して、その枠へ映像を描画します。64枠の構成なら、64個のゲーム実行用プロセスがそれぞれのゲームを動かします。管理側はROMの選択・起動・監視・入れ替えを担当し、起動準備の並列数を制限しながら、準備できた枠から表示します。

グループ表示では、起動時に「Mega Drive＋Mega-CD」「GB＋GBC＋GBA」などのグループを1つ抽選し、上キーで明示的に再抽選するまでそのグループを維持します。各枠のROMは個別に抽選するため、同じ系列のゲームが画面いっぱいに並び、それぞれ別の場面へ進みます。対象グループと通常表示との抽選比率は、後述の「グループ表示」で設定できます。

多画面での描画負荷を抑えるため、グループ表示は初期設定で各枠の表示更新を最大25fpsに制限します。エミュレーションの実行周期はコアが指定する速度に合わせ、表示更新の周期とは分けて管理しています。実際の速度や必要なCPU・メモリーは、機種・ROM・PCの性能によって変わります。

## 複数モニターへの配置

`config.json`の`multi_monitor`を`true`にすると、全画面表示でWindowsのモニター配置を取得し、モニターごとにタイルを並べます。異なる解像度の組み合わせに対応し、各ゲームの映像は縦横比を保って枠内に収めます。

グループ表示では、次の2台構成で合計64枠になります。

| モニターの解像度 | 配置（列×行） | 表示数 |
|---|---|---|
| 1920×1080 | 7×4 | 28枠 |
| 2560×1080 | 9×4 | 36枠 |
| **合計** | | **64枠** |

枠数は各モニターの解像度で決まります。グループ表示では2560×1080以外は7×4が基本です。FBNeo単独グループは負荷を考慮して各モニター4×4、2台で合計32枠にしています。モニター構成によってグループ表示の合計上限を超える場合は、通常表示へ戻ります。通常表示では、解像度と`max_slots_per_monitor`に応じた枠数を使います。

## 各枠が独立して入れ替わる非同期ローテーション

初期設定では`independent_slots_enabled`を有効にしており、各枠が別々の表示時間で動作します。時間を迎えた枠だけがフェードアウトし、次のROMを読み込んでフェードインする間も、ほかの枠は実行を続けます。通常表示・グループ表示のどちらでも、画面のあちこちが少しずつ入れ替わっていきます。

各枠の表示時間は、`cycle_seconds`を中心に`independent_jitter_seconds`の範囲で毎回ランダムに決まります。サンプルの共通設定は **150秒±15秒（135～165秒）** です。`systems/<機種ID>.json`に同じキーを指定すると、その機種の値を優先するため、起動に時間のかかる機種だけ長く表示することもできます。

時間は各コアから最初の映像フレームを受け取ってから数えます。起動時刻や表示時間の違いによって入れ替えのタイミングが分散し、フェード時間は`fade_duration_ms`で調整できます。待たずに切り替えたいときは、上キーでモード・グループから再抽選して全枠を、下キーでお気に入り枠だけを入れ替えられます。

## 必要なもの

Windows x64、Python、PyInstaller、および各機種のlibretroコア・ROM・必要なBIOSを用意してください。開発環境ではPython 3.14でテストしています。ROM・BIOS・個人のセーブ・お気に入り・ROM一覧はこのリポジトリに含みません。

## 配置先と書き込み権限

**アプリケーションのフォルダー全体を、スクリーンセーバーを実行するWindowsユーザーが書き込める場所へ配置してください。** 例：`%LOCALAPPDATA%\RetroNativeSaver`。

ログ出力を有効にした場合、EXE/SCRと同じ場所にある`logs/`へ実行ログを保存します（初期値はオフ）。また、お気に入りや、ROM一覧・ブラックリスト・ホワイトリストなどの`state/`内のファイルも書き込みます。設定したセーブ先にも書き込み権限が必要です。

`Program Files`や`C:\Windows\System32`など、書き込みが制限される場所への配置は避けてください。EXE/SCR、`_internal`、その他の同梱ファイルをまとめて配置し、そのフォルダーの`install_saver.bat`からWindowsへ登録してください。

## 初期設定とビルド

```powershell
python -m pip install -r requirements.txt
python initialize_config.py
```

初期化で`config.json`、`favorites.json`、`systems/`と空のホワイトリストを作成します。既存ファイルは上書きしません。サンプルの`C:/ROMs/<機種ID>`、`C:/RetroArch-win64/cores`、BIOSのパスを、ご自身の環境に合わせて編集してください。使用しない機種は`enabled`を`false`にしてください。

```powershell
.\build.bat
```

`dist/RetroNativeSaver/`に実行ファイル・SCR・必要な補助ファイルを作成します。配布先ではフォルダー全体を保持してください。ビルド時にも初期設定の不足分だけを作成します。

1. `dist/RetroNativeSaver/update_rom_catalog.bat`を実行して、固定ROM一覧を作成します。
2. `test_saver.bat`で表示を確認します。
3. `install_saver.bat`で登録し、Windowsのスクリーンセーバー設定を確認します。

ROMを追加・移動したら`update_rom_catalog.bat`で一覧を手動更新してください。既存の運用環境を更新する場合は、そちらの設定・save・state・お気に入りを保持してください。

X1の2ドライブ対応コアは専用ビルドです。DLLはGitに含めていません。[ビルド手順](cores/X1_BUILD.md)に従い、`cores/x1_rns_libretro.dll`を用意してください。その他のコアは外部のlibretroコアを使用します。

PC-98・X1・X68000・FM-7の`disk_boot_mode: "computer_two_drives"`では、`Disk 1 of N`／`Disk 2 of N`を補足のディスク番号より優先します。この表記がなければ、`Disk 1`／`Disk 2`または`Disk A`／`Disk B`をドライブ1・2に選びます。全体番号がある場合は、`(System)`や`(Disk 1)`などの既知の役割表記を除いて同じ組を探しますが、版やダンプの違いを示す表記は区別します。候補が複数に分かれる場合や起動ディスクがない場合は、起動を拒否します。

## 起動中の操作

| 操作 | 動作 |
|---|---|
| 左・右 | タイルを選択。操作が途切れると選択表示が消えます |
| Insert | 選択したゲームをお気に入りへ追加 |
| Delete | 通常枠ならブラックリストへ追加。お気に入り枠ならお気に入りから削除。その枠を入れ替え |
| 上 | 通常／グループ表示と機種グループを再抽選し、全枠を入れ替え |
| 下 | お気に入り枠だけ入れ替え |
| Enter | 選択したゲームをRetroArchへ引き継いで終了 |
| PageUp（ロールアップ）／PageDown（ロールダウン） | 全ディスプレイの縦タイル数を増減して設定に保存 |
| マウス移動・ホイール・ボタン・タッチ・その他の終了用キー | スクリーンセーバーを終了 |

セーバー専用のデスクトップからEnterで引き継ぐ場合は、専用スレッドで通常のWindowsデスクトップを参照します。既存のセーバー終了・回収処理を維持し、RetroArchはセーバーの終了に巻き込まれない形で起動します。画面の強制切り替えやWindowsのロック解除は行わず、ロック画面や認証が必要な状態ではこの引き継ぎを中止します。

`configure_favorites.bat`でお気に入りと起動後の入力を編集できます。`configure_rom_lists.bat`でROMリストを管理できます。

各枠の左上に「機種名 / ソフト名」を1行で表示し、枠内で右から左へ繰り返しスクロールします。両方とも機種名と同じフォント・`overlay.system_font_size`の文字サイズを使い、色は従来の設定を維持します。機種名からは設定例に含まれるコア名の補足を省き、ログには設定上の名前をそのまま残します。

既存設定からの更新時も、スクロールは初期状態で有効です。`overlay`内の`scroll_speed`（毎秒の移動ピクセル数、初期値24）、`scroll_pause_seconds`（左端での停止秒数、初期値2）、`scroll_gap`（繰り返しの最小間隔、初期値48ピクセル）で調整できます。短い名前もスクロールします。`scroll_speed`を`0`にすると1行の静止表示、`scroll_enabled`を`false`にすると従来の2行表示に戻り、`game_font_size`と`line_gap`が使われます。キー操作の案内・結果表示は静止したままです。その他の設定・セーブ・お気に入り・ROM選択は変更しません。

## 設定ダイアログ

**全般 → 縦タイル数**で通常表示・グループ表示の全画面配置を変更できます。`tile_rows: 0`（省略時も同じ）は、PageUp／PageDownを操作するまで従来の自動配置を維持します。`1`は各ディスプレイに1枠、`2`以上は画面の縦横比から列数を計算し、おおむね正方形の枠に並べます。ゲーム映像そのもののアスペクト比は維持します。4段の場合、1920×1080では7列×4段、2560×1080では9列×4段です。

枠の最小高さは270物理ピクセル（従来の1080px高・4段表示と同じ）です。画面自体が270px未満なら1段にします。解像度と全画面合計64枠の上限（FBNeoだけのグループは32枠）に合わせて段数を抑えます。`max_slots_per_monitor`は従来の通常自動配置だけに適用します。新しい通常配置でも機種別の同時起動数・resourceの上限は維持するため、上限に達した枠は空く場合があります。v0.22.4からは、通常64枠表示のための余裕を持たせるため、GB・GBC・Game Gear・Master System・Mega Drive・NES・SNES・PC Engine・SG-1000の設定例で、同時起動上限を各6本にしています。通常の`heavy_cd.max_weight`の設定例は7のままです。利用可能なROM、お気に入りの予約枠、起動失敗によって埋まる枠数は変わります。**既存環境の更新時：** `systems/*.json`は保持されるため、EXE/SCRの差し替えだけでは上限は変わりません。同じ調整を適用する場合は、設定画面の**機種別 → 表示・負荷**で上記9機種の「通常表示の同時起動数」（`max_concurrent`）を`6`にして保存し、セーバーを起動し直してください。ROM・コアのパスや他の設定は維持してください。

`tile_resize_keys_enabled: true`（既定）では、PageUp（ロールアップ）で全ディスプレイの段数を増やし、PageDown（ロールダウン）で減らします。1回押すごとに1段変わり、長押しによる自動反復は無視します。連続操作の保存をまとめ、最新のJSONへ`tile_rows`だけを反映してバックアップ・置換保存します。保存に失敗した場合は配置を維持し、ログが有効なら理由を記録します。非同期表示では残るゲームを継続し、余った子プロセスを安全に終了して、増えた枠を順次起動します。同期表示では既存の終了・プロセス再起動経路を使って新しい周期へ移ります。プレビュー・ウィンドウ表示・明示した`--slots`は従来どおりです。マウスホイールは常に終了操作です。`tile_resize_keys_enabled: false`ではPageUp／PageDownも終了操作になります。v0.22.1の`tile_wheel_enabled`は新しい有効／無効設定がない場合にだけ引き継ぎ、ホイールへ操作を割り当てることはありません。

Windowsのスクリーンセーバー設定の **「設定」**、RandomSaverの設定画面呼び出し、または`configure_saver.bat`から開けます。EXE/SCRは`/c`・`/c:HWND`・`/c HWND`に対応し、`--config <パス>`を追加すると別の既存設定ファイルを開けます。

**全般 → Language / 言語**で**自動（Windows）・English・日本語**を選べます。初期値は自動で、`ui_language`がない既存設定もWindowsの表示言語が日本語なら日本語、それ以外は英語になります。「適用／OK」で保存して画面を開き直すと反映されます。お気に入り・自動入力・ROM選択・ブラック／ホワイトリスト・アプリのメッセージにも同じ設定を使います。JSONには`ui_language`を`auto`・`en`・`ja`で保存します。ゲーム名・ユーザーが指定した機種名・パスは変更しません。Windows標準のファイル選択・ボタン・OS由来のエラー詳細は、Windows側の言語になる場合があります。

- **全般**：複数モニター、共通の表示時間とランダム幅、非同期表示、上限FPS、フェード、キー操作、ログ出力。
- **タイトル表示**：1行スクロール、文字サイズ、色、間隔、背景の濃さ。
- **グループ表示**：抽選の有効／無効、通常表示との割合、上限FPS、既存グループ内の使用機種。グループ構成や負荷上限の定義はJSONに維持します。
- ボタンから既存のお気に入り・キー入力画面、ブラック／ホワイトリスト画面を開けます。ROM一覧の更新ではエミュレーターを起動しません。

**OK**は保存して閉じる、**適用**は保存、**キャンセル**は画面内の未保存変更を破棄します。次回のセーバー起動から反映されます。管理画面は保存済み設定を参照し、それぞれ独立して保存するため、管理画面側で保存した変更はキャンセルでは戻りません。ROM一覧更新中は完了を待ってから設定画面を閉じます。

変更した設定だけを`config.json`に反映し、未知のキー、明示されたグループ、旧形式の設定、機種別ファイルを保持します。開くだけ・無変更での適用では書き込みません。保存時は元のファイルを`config.json.bak-...`へバックアップし、ファイルを一括置換します。JSONの整形は変わる場合があります。JSONが壊れている場合や外部で変更された場合は上書きしません。既存の設定ファイルが必要で、エラー時に初期値を勝手に作成しません。

**ログ出力の初期値はオフ**です。新しい`log_output_enabled`キーがない既存設定でもオフになります。**全般 → ログを出力する**をオンにするか、`"log_output_enabled": true`を指定すると、`logs/`への日次ログ保存を再開します。親・実行子・各枠・監視プロセスで起動時の選択を共有します。オフにしても過去ログの削除、メモリー上の異常監視の停止、回収処理・セーブ・お気に入り・ROMリスト状態の変更は行いません。明示的な計測起動`RNS_STARTUP_TIMING=1`は指定どおり計測ログを作成します。コアが独自に作成するファイルは、このアプリケーションログ設定の対象外です。

### 機種別設定とRetroArch

**「機種別」**タブのセレクトボックスには、`systems_dir`で指定したフォルダー内の機種を、無効な機種も含めて表示します。機種を選ぶと、有効／無効、表示名、コアDLL、ROM・BIOS・セーブ・アセットのフォルダー、表示時間、同時起動数・負荷、描画方式、ROM検索・ディスク起動方式、互換性フラグ、タイトル情報、コアオプションを編集できます。コアオプションは設定名と値を手入力します。画面を開く際にコアを読み込むことはありません。機種ID・未編集項目・未知のJSONキーは維持します。不正なファイルは一覧にエラーとして表示し、他機種の編集を妨げません。

機種を切り替えても編集中の値を保持します。**適用／OK**で共通設定と編集した全機種のファイルを保存し、機種の切り替えだけでは保存しません。省略可能な項目で**「共通／既定を使用」**を選ぶと機種別キーを取り除き、既存の共通値・既定値への継承を使います。一時セーブ領域を使う設定はセーブ先の指定より優先されます。グループ表示の同時起動数は引き続きグループ用の上限に従います。ROMフォルダー・拡張子などの検索条件を変えた後は、保存して**「ROM一覧を更新」**してください。画面にも案内を表示し、一覧更新中の設定保存は止めます。

編集した全ファイルの入力と外部変更を確認してから保存を開始します。バックアップと一括置換はファイル単位です。途中で書き込みに失敗した場合は保存済みのファイルを明示し、残りの編集を保持して再試行できます。全ファイルを一度に置き換える処理ではありません。キャンセルで破棄するのは未保存の編集だけです。

**「全般 → RetroArchのEXE」**では、選択したゲームをEnterで開くときの実行ファイルを参照ボタンから指定できます。既存の`config.json`の`retroarch_path`へ保存します。従来はJSONからのみ指定できた設定です。空欄では従来どおり、選択したコアのフォルダーの1階層上、次に使用するBIOSフォルダーの1階層上の`retroarch.exe`を探します。明示指定がある場合はそのパスを優先し、見つからなくても別のEXEへ勝手に切り替えません。引き継ぎ処理やエミュレーターの起動方式は変更していません。

## グループ表示

初期設定は通常表示50%／グループ表示50%です。`single_system_mode.normal_weight`と`grouped_weight`の比で変更できます。グループは起動時に1つ選び、自動ローテーションではそのグループ内でROMを入れ替えます。上キーを押すと設定の比率でモードを再抽選し、グループ表示なら機種グループも選び直します。同じモード・グループが続く場合もあります。保存したタイル段数、お気に入り、負荷上限、起動中の障害による除外情報は維持します。診断用の明示指定（`--presentation`・`--system`・`--slots`・ウィンドウ表示）は引き続き優先され、単独の`--worker`実行では従来のROM入れ替えになります。

```json
[
  ["megadrive", "megacd"],
  ["pcengine", "pcenginecd", "pcfx"],
  ["gb", "gbc", "gba"],
  ["fds", "nes"],
  ["snes"],
  ["fbneo"],
  ["msx", "x1", "x68000", "pc88", "pc98"],
  ["neocd"]
]
```

`single_system_mode.disabled_systems`の機種はグループ表示から除外します。サンプルでは`["fbneo"]`でFBNeoを停止しています。`[]`で再開できます。通常表示の機種設定には影響しません。表示更新の上限は`single_system_mode.max_fps`で指定し、共通の`independent_max_fps`との小さい方を使います。初期設定では25fpsです。

PC Engine／CD-ROM²グループにはPC-FXも追加できます。既存のグループ一覧を明記している場合は同じ配列に`"pcfx"`を追加するか、v0.21.23以降へ更新後、設置先の`enable_pcfx_group.bat`を実行してください。バッチは`config.json`をバックアップしてから更新し、その他の設定値は維持します。PC-FXは既存のコア・BIOSと`heavy_cd・weight=1`を使用し、自動ボタン入力は追加しません。グループ表示用の負荷上限を使い、通常表示の上限は変更しません。PC-FXを含む多数枠の実機性能は、ご使用の環境で確認が必要です。
